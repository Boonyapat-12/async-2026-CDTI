บท 2 — Coroutine, Awaitable และ Event Loop
========================================================================

[CORO-01] แยก function / object / task
async def fetch(): ... นิยาม coroutine function
fetch() สร้าง coroutine object; ยังไม่ schedule โดยการเรียกเพียงอย่างเดียว
await fetch() รันและรอ coroutine จากภายใน coroutine อื่น
asyncio.create_task(fetch()) สร้าง Task และ schedule ให้ loop
asyncio.run(main()) เป็นจุดเริ่มโปรแกรมสคริปต์และจัดการ loop ให้
ใน environment ที่มี loop รันอยู่แล้ว เช่นบาง notebook ใช้ await main()

Awaitable คือสิ่งที่ await ได้ เช่น coroutine, Task, Future
Future แทนผลลัพธ์ที่ยังไม่พร้อม พบใน API ระดับล่าง ไม่จำเป็นต้องสร้างเองบ่อย

[LOOP-01] Event loop ทำอะไร?
1. เลือก task/callback ที่พร้อม
2. รันต่อจนงานจบหรือพักรอสิ่งที่ยังไม่พร้อม
3. เฝ้ารอ timer/I/O แล้วนำงานกลับเข้าสู่คิวพร้อมทำ
ใน event loop thread เดียว task ไม่รัน Python code พร้อมกันจริง
await ไม่รับประกันว่าจะสลับ task ทุกครั้ง หาก awaitable พร้อมแล้วอาจทำต่อทันที
asyncio.sleep(0) ใช้ยอมคืนการควบคุมอย่างชัดเจน

[CORO-02] อ่านโค้ดอย่างเป็นขั้นตอน
ขีดเส้นใต้ create_task / gather ว่างานเริ่มถูก schedule ตรงไหน
วง await ที่อาจพักรอ แล้วดูว่ามีงานอื่นพร้อมทำหรือไม่
ติดตาม return ว่าคืนให้ใคร และ print เกิดก่อนหรือหลังจุดรอ
อย่าสับสนลำดับ print ระหว่างงานกับลำดับผลลัพธ์ของ gather

อ้างอิง repo: Week2/asyncio01.py ถึง asyncio04.py,
Week2/asyncio10.py และ Week3/task_06_loop_introspection.py

[CODE coroutine_basic]
import asyncio  # ใช้ coroutine และ event loop
async def greet():  # นิยาม coroutine function
    await asyncio.sleep(0)  # ยอมคืนการควบคุม
    return "hello"  # ส่งค่ากลับให้ผู้ await
async def main():  # จุดรวม workflow
    print(await greet())  # รัน greet และอ่านค่าที่คืน
asyncio.run(main())  # เริ่ม loop ในสคริปต์
[END CODE]

คำสั่งรัน: คัดลอก CODE เป็น demo.py แล้วใช้ python demo.py
ผลที่คาดหวัง: hello
ปรับใช้: เปลี่ยน greet เป็น fetch หรือ compute และเก็บค่าจาก await

[LOOP-02] ทำไม loop ค้าง?
while True ที่ไม่มีการพักรอ -> task อื่นไม่ได้เดิน
time.sleep / requests.get บน loop thread -> บล็อก loop
งาน CPU หนัก -> ย้ายไป process ตามความเหมาะสม
asyncio.to_thread() เหมาะกับ blocking I/O; การ cancel ผู้รอไม่ได้หยุด thread ทันที

1. Week2 กำลังเรียนเรื่องอะไร
-----------------------------

Week2 เรียนเรื่อง Asynchronous Programming หรือการเขียนโปรแกรมให้ “รอหลายงานได้ฉลาดขึ้น”
โดยเฉพาะงานที่มีช่วงรอ เช่น

- รออาหารสุก
- รอกาแฟชงเสร็จ
- รอไฟล์ดาวน์โหลด
- รอข้อมูลจากอินเทอร์เน็ต
- รอ database ตอบกลับ

ปัญหาคือ ถ้าเราเขียนแบบปกติ โปรแกรมจะทำงานแบบนี้:

[โค้ด / แผนภาพ : text]
ทำงาน A -> รอ A เสร็จ -> ทำงาน B -> รอ B เสร็จ -> ทำงาน C -> รอ C เสร็จ
[จบโค้ด / แผนภาพ]

แต่ asynchronous programming ทำให้โปรแกรมทำงานประมาณนี้:

[โค้ด / แผนภาพ : text]
เริ่มงาน A -> ระหว่าง A รอ ให้ไปเริ่มงาน B -> ระหว่าง B รอ ให้ไปเริ่มงาน C -> กลับมาเก็บงานที่เสร็จ
[จบโค้ด / แผนภาพ]

สิ่งสำคัญ: asyncio ไม่ได้แปลว่ามีหลาย CPU หรือหลาย thread เสมอไปค่ะ
โดยทั่วไป asyncio คือ งานหลายงานสลับกันทำใน thread เดียว ผ่าน event loop

2. คำศัพท์สำคัญที่ต้องรู้ก่อน
-----------------------------

- คำ: synchronous
  แปลแบบง่าย: ทำทีละอย่างตามลำดับ
  จำแบบร้านอาหาร: ทำอาหารจาน A ให้เสร็จก่อน ค่อยเริ่มจาน B

- คำ: asynchronous
  แปลแบบง่าย: ทำงานแบบสลับระหว่างช่วงรอ
  จำแบบร้านอาหาร: ระหว่างต้มเส้นอยู่ ไปชงกาแฟให้ลูกค้าอีกคนได้

- คำ: coroutine
  แปลแบบง่าย: งาน async ที่ยังไม่ถูกรันจริง
  จำแบบร้านอาหาร: ใบสั่งงานที่เขียนไว้ แต่ยังไม่ได้เอาเข้าครัว

- คำ: event loop
  แปลแบบง่าย: ตัวจัดคิวงาน async
  จำแบบร้านอาหาร: ผู้จัดการครัวที่คอยดูว่างานไหนรอ งานไหนทำต่อได้

- คำ: async def
  แปลแบบง่าย: ประกาศ function แบบ async
  จำแบบร้านอาหาร: เขียนสูตรงานที่ให้ event loop จัดการได้

- คำ: await
  แปลแบบง่าย: จุดที่บอกว่า “ตอนนี้รอได้ ไปทำงานอื่นก่อนได้”
  จำแบบร้านอาหาร: ต้มเส้น 1 นาที ระหว่างนี้ไปทำอย่างอื่นก่อน

- คำ: task
  แปลแบบง่าย: coroutine ที่ถูกส่งให้ event loop รัน
  จำแบบร้านอาหาร: ใบสั่งงานที่ถูกเอาเข้าคิวครัวแล้ว

- คำ: asyncio.run()
  แปลแบบง่าย: เปิด event loop แล้วรันงานหลัก
  จำแบบร้านอาหาร: เปิดร้าน แล้วเริ่มให้ผู้จัดการครัวทำงาน

- คำ: asyncio.create_task()
  แปลแบบง่าย: สร้าง task ให้เริ่มรันแบบ concurrent
  จำแบบร้านอาหาร: ส่งออเดอร์เข้าครัวโดยไม่ต้องยืนรอหน้าหม้อ

- คำ: asyncio.gather()
  แปลแบบง่าย: รอหลาย task พร้อมกัน
  จำแบบร้านอาหาร: รอทุกออเดอร์ในชุดนี้เสร็จทั้งหมด

4.1 asyncio01.py — The First Coroutine Function
-----------------------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
async def greet():
    print("Hello from the Coroutine")

print(type(greet))
[จบโค้ด / แผนภาพ]

จุดสำคัญ:

- async def greet() คือการประกาศ function แบบ async
- แต่ตัว greet เองยังเป็น function อยู่
- ยังไม่มีข้อความ Hello from the Coroutine ออกมา เพราะยังไม่ได้เรียกและยังไม่ได้รันด้วย
  event loop

สิ่งที่ควรจำ:

[โค้ด / แผนภาพ : text]
async def = สร้าง function ที่สามารถกลายเป็น coroutine ได้
[จบโค้ด / แผนภาพ]

4.2 asyncio02.py — The Coroutine Object
---------------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
coro_object = greet()
print(type(coro_object))
coro_object.close()
[จบโค้ด / แผนภาพ]

จุดสำคัญ:

- พอเรียก greet() จะได้ coroutine object
- coroutine object ยังไม่ทำงานเอง
- ถ้าสร้าง coroutine แล้วไม่รัน ควร close() เพื่อไม่ให้ Python เตือนว่า coroutine was
  never awaited

เปรียบเทียบง่าย ๆ:

[โค้ด / แผนภาพ : text]
greet       = สูตรอาหาร

greet()     = ใบสั่งอาหารที่ถูกเขียนแล้ว

await/run   = เอาใบสั่งอาหารไปให้ครัวทำจริง
[จบโค้ด / แผนภาพ]

4.3 asyncio03.py — The Event Loop
---------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
coro_object = greet()
asyncio.run(coro_object)
[จบโค้ด / แผนภาพ]

จุดสำคัญ:

- asyncio.run() คือการเปิด event loop
- event loop จะรับ coroutine ไปทำงานจริง
- ตอนนี้ข้อความใน greet() ถึงจะ print ออกมา

จำสั้น ๆ:

[โค้ด / แผนภาพ : text]
coroutine จะทำงานจริงเมื่อถูก await หรือถูกส่งให้ event loop ผ่าน asyncio.run()
[จบโค้ด / แผนภาพ]

4.4 asyncio04.py — The await Keyword
------------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
async def main():
    print("Task Started")
    await asyncio.sleep(1)
    print("Task Finished")
[จบโค้ด / แผนภาพ]

await asyncio.sleep(1) ไม่เหมือน time.sleep(1):

- คำสั่ง: time.sleep(1)
  พฤติกรรม: block thread ทิ้งไว้ 1 วินาที ทำอย่างอื่นไม่ได้

- คำสั่ง: await asyncio.sleep(1)
  พฤติกรรม: รอ 1 วินาทีแบบคืน control ให้ event loop ไปจัดการงานอื่นได้


ในไฟล์นี้มี task เดียว เลยยังไม่เห็นความต่างมาก แต่เป็นพื้นฐานของไฟล์ถัดไปค่ะ

4.5 asyncio05.py — Sequential Execution
---------------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
await serve_customer("A")
await serve_customer("B")
[จบโค้ด / แผนภาพ]

ถึงจะเป็น async function แต่ถ้าเขียน await ต่อกันตรง ๆ แบบนี้:

[โค้ด / แผนภาพ : text]
รอ A เสร็จ -> ค่อยเริ่ม B
[จบโค้ด / แผนภาพ]

ดังนั้นถ้า A ใช้ 1 วินาที และ B ใช้ 1 วินาที เวลารวมจะประมาณ 2 วินาที

ข้อควรจำ:

[โค้ด / แผนภาพ : text]
async ไม่ได้ทำให้เร็วเอง ถ้า await ทีละอันแบบเรียงกัน ก็ยัง sequential
[จบโค้ด / แผนภาพ]

4.6 asyncio06.py — Creating a Concurrent Task
---------------------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
task1 = asyncio.create_task(cook_spaghetti("A"))
print("Main program can do other things...")
await task1
[จบโค้ด / แผนภาพ]

จุดสำคัญ:

- asyncio.create_task(...) ส่ง coroutine เข้า event loop
- task เริ่มมีโอกาสทำงานแบบเบื้องหลัง
- main program ยังสามารถทำงานอื่นต่อได้
- สุดท้ายต้อง await task1 เพื่อรอให้ task เสร็จ

ภาพจำ:

[โค้ด / แผนภาพ : text]
create_task = ฝากงานไว้กับ event loop ก่อน
await task  = กลับมารอรับผลลัพธ์ตอนต้องการ
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

4.7 asyncio07.py — Dual Tasks Concurrency
-----------------------------------------

แนวคิดหลัก:

[โค้ด / แผนภาพ : python]
task_a = asyncio.create_task(cook_spaghetti("A"))
task_b = asyncio.create_task(cook_spaghetti("B"))

await task_a
await task_b
[จบโค้ด / แผนภาพ]

ทำไมเวลารวมประมาณ 1 วินาที ไม่ใช่ 2 วินาที?

เพราะ task A และ task B ถูกสร้างก่อนทั้งคู่ จากนั้นทั้งสอง task มีโอกาสเริ่มทำงานพร้อม ๆ
กันใน event loop

ลำดับประมาณนี้:

[โค้ด / แผนภาพ : text]
สร้าง task A
สร้าง task B
A เริ่มทำอาหาร -> await sleep
B เริ่มทำอาหาร -> await sleep
A เสร็จ
B เสร็จ
[จบโค้ด / แผนภาพ]

ข้อควรจำ:

[โค้ด / แผนภาพ : text]
ถ้าต้องการ concurrency ต้องสร้าง task ก่อน แล้วค่อย await
[จบโค้ด / แผนภาพ]

4.8 asyncio08.py — Task Interleaving
------------------------------------

ไฟล์นี้แสดงภาพการสลับงานชัดมาก:

[โค้ด / แผนภาพ : python]
task_kitchen = asyncio.create_task(kitchen_crew())
task_bar = asyncio.create_task(bar_crew())

await task_kitchen
await task_bar
[จบโค้ด / แผนภาพ]

สิ่งที่ควรสังเกต:

- kitchen เริ่มต้มเส้นแล้ว await asyncio.sleep(1)
- ระหว่าง kitchen รอ event loop ไปให้ bar ทำงาน
- bar เริ่มบดกาแฟแล้ว await asyncio.sleep(1)
- พอเวลาครบ event loop กลับมาให้แต่ละ task ทำต่อ

นี่คือหัวใจของ asyncio:

import threading
from time import sleep, ctime, time


def cook_spaghetti(customer):
    thread_name = threading.current_thread().name
    print(f"{ctime()} -> [{thread_name}] Start cooking spaghetti for customer {customer}")
    sleep(2)
    print(f"{ctime()} -> [{thread_name}] Finished spaghetti for customer {customer}")


def main():
    start = time()
    customers = ["A", "B", "C"]
    threads = []

    for customer in customers:
        t = threading.Thread(
            target=cook_spaghetti,
            args=(customer,),
            name=f"Chef-{customer}"
        )
        threads.append(t)
        t.start()

    for t in threads:
        t.join()

    print(f"Total time: {time() - start:.2f} seconds")


if __name__ == "__main__":
    main()

import asyncio
from time import ctime, time

    tasks = []

    for customer in customers:
        task = asyncio.create_task(cook_spaghetti(customer))
        tasks.append(task)

    await asyncio.gather(*tasks)

    print(f"Total time: {time() - start:.2f} seconds")


if __name__ == "__main__":

14. ข้อผิดพลาดที่เจอบ่อย
------------------------

14.1 เรียก async function แล้วไม่มีอะไรเกิดขึ้น
-----------------------------------------------

ผิด:

[โค้ด / แผนภาพ : python]
async def main():
    print("Hello")

main()
[จบโค้ด / แผนภาพ]

เพราะ main() จะคืน coroutine object แต่ยังไม่รันจริง

ถูก:

[โค้ด / แผนภาพ : python]
asyncio.run(main())
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

14.2 ใช้ time.sleep() ใน async function
---------------------------------------

ผิด:

[โค้ด / แผนภาพ : python]
async def cook():
    time.sleep(2)
[จบโค้ด / แผนภาพ]

เพราะมัน block ทั้ง event loop

ถูก:

[โค้ด / แผนภาพ : python]
async def cook():
    await asyncio.sleep(2)
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

14.3 สร้าง task แล้วไม่ได้ await
--------------------------------

ผิด:

[โค้ด / แผนภาพ : python]
asyncio.create_task(cook_spaghetti("A"))
[จบโค้ด / แผนภาพ]

ถ้า main จบเร็ว task อาจยังทำไม่เสร็จ

ถูก:

[โค้ด / แผนภาพ : python]
task = asyncio.create_task(cook_spaghetti("A"))
await task
[จบโค้ด / แผนภาพ]

หรือหลาย task:

[โค้ด / แผนภาพ : python]
await asyncio.gather(*tasks)
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

14.4 ลืม comma ใน args
----------------------

ผิด:

[โค้ด / แผนภาพ : python]
args=(customer)
[จบโค้ด / แผนภาพ]

ถูก:

[โค้ด / แผนภาพ : python]
args=(customer,)
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

14.5 ลืม if __name__ == "__main__" ใน multiprocessing
-----------------------------------------------------

ควรมีเสมอ:

[โค้ด / แผนภาพ : python]
if __name__ == "__main__":
    main()
[จบโค้ด / แผนภาพ]

โดยเฉพาะตอนรันบน Windows ค่ะ

16. สรุปสุดท้ายแบบจำง่าย
------------------------

[โค้ด / แผนภาพ : text]
simple          = ทำทีละงาน ช้าที่สุด แต่อ่านง่ายสุด
threading       = หลาย thread เหมาะกับงานรอ / I/O
multiprocessing = หลาย process เหมาะกับงาน CPU หนัก
asyncio         = thread เดียว + event loop เหมาะกับงานรอจำนวนมาก
[จบโค้ด / แผนภาพ]

สำหรับ Week2 ให้จำหัวใจของ asyncio แบบนี้ค่ะ:

[โค้ด / แผนภาพ : text]
async def สร้าง coroutine
await คือจุดที่ยอมให้ event loop ไปทำงานอื่น
create_task ทำให้งานเริ่ม concurrent
gather ใช้รอหลาย task พร้อมกัน
asyncio.run ใช้เปิด event loop
[จบโค้ด / แผนภาพ]
