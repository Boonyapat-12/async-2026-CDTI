========================================================================

[QUEUE-01] FIFO และหน้าที่
Producer สร้างงานแล้ว put; Consumer get แล้วประมวลผล
FIFO รับประกันลำดับนำออกตามคิว ไม่รับประกันลำดับงานเสร็จเมื่อมีหลาย worker
Head เป็นจุดนำออก; Tail เป็นจุดเพิ่มเข้า
Queue แยกอัตราผลิตกับอัตราประมวลผล และช่วยแบ่งงานให้ worker

[QUEUE-02] API จำเป็น
await q.put(x): รอพื้นที่ถ้าคิวเต็ม
await q.get(): รอข้อมูลถ้าคิวว่าง
q.put_nowait(x): ไม่รอ; คิวเต็ม -> QueueFull
q.get_nowait(): ไม่รอ; คิวว่าง -> QueueEmpty
q.task_done(): แจ้งหนึ่งงานที่ get มาได้รับการจัดการแล้ว ไม่ await
await q.join(): รอ unfinished task count เป็นศูนย์ ไม่ใช่ดูแค่ q.empty()
get() ไม่ลด unfinished count; task_done() จึงต้องเรียกให้ตรงจำนวน
task_done() มากเกินจำนวน put เกิด ValueError

[QUEUE-03] Bounded queue
maxsize=2 เก็บ item ที่ยังอยู่ในคิวได้สูงสุด 2 ไม่รวมงานที่ worker get ไปแล้ว
maxsize<=0 ไม่จำกัดขนาด; อาจใช้ memory มากถ้าผลิตเร็วกว่าประมวลผล
Backpressure: producer รอพื้นที่ ทำให้การผลิตถูกชะลอตามความสามารถผู้รับ
asyncio.Queue ใช้กับ coroutine ใน loop ไม่ใช่ queue ข้าม thread/process

[QUEUE-04] หยุด worker ด้วย sentinel
ใช้ None เมื่อ payload ปกติไม่เป็น None; worker หลายตัวต้องส่งเท่าจำนวน worker
join ไม่ได้หยุด worker ต้องกำหนด lifecycle แยกต่างหาก
ตัวอย่างถือว่างานที่ get มาได้รับการจัดการสำเร็จ/ล้มเหลวเมื่อออก finally
หากงานล้มเหลวและต้อง retry ต้องออกแบบ retry/error queue เพิ่มเอง

[CODE queue_workers]
import asyncio  # ใช้ queue และ worker
async def main():
    queue = asyncio.Queue(maxsize=2)  # จำกัดงานรอในคิว
    results = []  # เก็บผลของตัวอย่าง
    async def worker():
        while True:
            item = await queue.get()  # รอและรับงาน
            try:
                if item is None:  # sentinel หยุด worker
                    return
                await asyncio.sleep(0)  # จำลองงานที่รอได้
                results.append(item * 2)  # ประมวลผล
            finally:
                queue.task_done()  # ตรงกับทุก get รวม sentinel
    workers = [asyncio.create_task(worker()) for _ in range(2)]
    for item in (1, 2, 3):  # ผลิตสามงาน
        await queue.put(item)
    for _ in workers:  # ส่ง sentinel คนละหนึ่ง
        await queue.put(None)
    await queue.join()  # รอการบัญชีงานครบ
    await asyncio.gather(*workers)  # รอ worker หยุดจริง
    print(sorted(results))  # ไม่สมมติลำดับเสร็จของ worker
asyncio.run(main())  # เริ่มสคริปต์
[END CODE]

[QUEUE-05] แก้คิวค้าง
join ค้าง -> ลืม task_done / producer ยังเติม / worker fail ก่อนรับงานที่เหลือ
put ค้าง -> คิวเต็มและไม่มี consumer เดิน
get ค้าง -> ไม่มีข้อมูลใหม่และไม่มี sentinel
อย่าแก้ด้วย task_done แบบเดา: ต้องตามบัญชีงานจริง

1. พื้นฐาน Queue และ FIFO
=========================

Queue คืออะไร?
--------------

Queue ถูกสร้างขึ้นเพื่อจัดการ ลำดับการเข้ามาของข้อมูล (order of arrival) ในระบบดิจิทัล
โดยเลียนแบบแถวรอในชีวิตจริง

FIFO — First-In, First-Out
--------------------------

หลักสำคัญของ Queue คือ

เข้าก่อน → ออกก่อน

ข้อมูลที่ถูกเพิ่มเข้ามาก่อน จะถูกนำไปประมวลผลก่อน

ตัวอย่าง
- แถวจ่ายเงินในซูเปอร์มาร์เก็ต
- สายการผลิตในโรงงาน
- แถวรอลูกค้าใน Call Center

2. โครงสร้างภายใน Queue
=======================

Head และ Tail
-------------

- ส่วน: Head
  หน้าที่: จุดที่นำข้อมูลออก / Dequeue

- ส่วน: Tail
  หน้าที่: จุดที่เพิ่มข้อมูลเข้า / Enqueue


Enqueue
------------

เพิ่มข้อมูลใหม่เข้า Queue ที่ Tail

Dequeue
------------

นำข้อมูลเก่าสุดออกจาก Queue ที่ Head

Time Complexity
---------------

Queue มีแนวคิดให้

[โค้ด / แผนภาพ : text]
Enqueue = O(1)
Dequeue = O(1)
[จบโค้ด / แผนภาพ]

ไม่ว่าจะมีข้อมูลประมาณ 10 รายการ หรือ 1,000,000 รายการ เวลาในการทำงานของ operation
ยังคงเป็นค่าคงที่ตามแนวคิดของ Queue ในเอกสาร

📌 หน้า 4: Head, Tail, Enqueue, Dequeue และ O(1)

2.1 Circular Buffer
-------------------

Circular Buffer เป็นการจองพื้นที่หน่วยความจำแบบมีขนาดคงที่ แล้วให้ตำแหน่ง Head/Tail
หมุนวนกลับมาใช้พื้นที่เดิม

แนวคิดง่าย ๆ:

[โค้ด / แผนภาพ : text]
[0] [1] [2] [3] [4] [5]
 ↑                   ↑
Head                Tail
[จบโค้ด / แผนภาพ]

เมื่อข้อมูลที่ Head ถูกนำออก ช่องนั้นจะกลับมาใช้สำหรับข้อมูลใหม่ได้
โดยไม่ต้องเลื่อนข้อมูลทั้งหมด

สิ่งสำคัญ
------------

- Fixed-size allocation
- มี Head Pointer
- มี Tail Pointer
- ใช้ Modulo % เพื่อวนกลับต้น Buffer

ตัวอย่างแนวคิด:

[โค้ด / แผนภาพ : text]
(Tail + 1) % N
[จบโค้ด / แผนภาพ]

2.2 Linked List
---------------

Linked List เป็นการจองหน่วยความจำแบบ Dynamic

แต่ละ Node มี:

[โค้ด / แผนภาพ : text]
Data + Next Pointer
[จบโค้ด / แผนภาพ]

Next Pointer จะชี้ไปยัง Node ถัดไป

จุดเด่น
------------

- เพิ่ม Node ตามจำนวนข้อมูลที่เข้ามา
- ขยายได้ตามต้องการจนกว่า RAM จะหมด
- เหมาะกับ Queue ที่ต้องการขนาด Dynamic

ข้อควรระวัง
------------

การสร้างและลบ Node บ่อย ๆ ทำให้เกิด Allocation/Deallocation overhead

3. Queue ช่วยแยกระบบอย่างไร
===========================

System Decoupling
-----------------

ถ้า System A เรียก System B โดยตรง:

[โค้ด / แผนภาพ : text]
System A ───────► System B
[จบโค้ด / แผนภาพ]

ถ้า B ช้าหรือหยุดทำงาน A ก็อาจได้รับผลกระทบทันที

Queue ทำหน้าที่เป็น Middleman

[โค้ด / แผนภาพ : text]
Producer ──► Queue ──► Consumer
[จบโค้ด / แผนภาพ]

Producer และ Consumer ไม่จำเป็นต้องรู้รายละเอียดภายในของกันและกัน

Queue จึงเป็นจุดกลางในการส่งต่องาน

4. Queue เป็น Buffer
====================

Queue สามารถทำหน้าที่เป็น Buffer เพื่อรับมือกับ Traffic Spike

ตัวอย่าง:

[โค้ด / แผนภาพ : text]
ช่วงปกติ
Producer → → → Queue → Consumer

ช่วงข้อมูลพุ่งสูง
Producer → → → → → → Queue → Consumer
                   ↑
              Buffer รองรับ
[จบโค้ด / แผนภาพ]

ถ้ามีข้อมูลเข้ามาเร็วมาก Queue จะช่วยเก็บงานที่เข้ามาก่อน เพื่อไม่ให้ Backend
ถูกโจมตีด้วยงานจำนวนมากพร้อมกัน

📌 หน้า 10: Buffer Mechanism for Traffic Spikes

----------------------------------------------------------------

Load Leveling
-------------

Queue ช่วยเปลี่ยน

[โค้ด / แผนภาพ : text]
Traffic ไม่สม่ำเสมอ
████████████████
██
████████████
[จบโค้ด / แผนภาพ]

ให้กลายเป็นการประมวลผลที่สม่ำเสมอมากขึ้น

[โค้ด / แผนภาพ : text]
Consumer
████ ████ ████ ████
[จบโค้ด / แผนภาพ]

Pull-Based Pattern
------------------

Consumer เป็นฝ่าย ดึงงานจาก Queue

ไม่ใช่ Producer บังคับส่งงานให้ Consumer โดยตรง

[โค้ด / แผนภาพ : text]
Producer → Queue ← Consumer
                    ↑
              ดึงตามความสามารถ
[จบโค้ด / แผนภาพ]

Consumer

- Web page downloader
- Analytics engine

Queue
------------

[โค้ด / แผนภาพ : text]

   │
   ▼
 Queue
   │
   ▼
Consumer

6. Multiple Consumers
=====================

ถ้างานเยอะ สามารถเพิ่ม Consumer ได้หลายตัว

[โค้ด / แผนภาพ : text]

7. Blocking Queue vs Async Queue
================================

7.1 Blocking Queue
------------------

เมื่อ Queue ว่าง Consumer จะรอ/Block

[โค้ด / แผนภาพ : text]
Queue ว่าง
   ↓
Consumer รอ
   ↓
ข้อมูลมา
   ↓
Consumer ทำงาน
[จบโค้ด / แผนภาพ]

ข้อดี:
- เข้าใจง่าย
- Thread-safe

ข้อเสีย:
- Thread ถูกใช้เพื่อรอ
- ถ้ามี Thread จำนวนมากจะสิ้นเปลือง Resource

📌 หน้า 18–20: Blocking Queue และกรณี Queue เต็ม

----------------------------------------------------------------

7.2 Non-Blocking / Event-Driven Queue
-------------------------------------

แนวคิดคือ

Yield and Switch

ถ้า Queue ว่าง Consumer จะไม่ทำให้ทั้งโปรแกรมหยุด

แต่จะ:

[โค้ด / แผนภาพ : text]
Consumer รอ Queue
      ↓
Yield control
      ↓
Event Loop ไปทำ Task อื่น
      ↓
มีข้อมูลเข้า Queue
      ↓
กลับมาทำ Consumer
[จบโค้ด / แผนภาพ]

จึงใช้ Resource ได้มีประสิทธิภาพกว่าในระบบ Async

8. asyncio.Queue
================

asyncio.Queue คือ Queue ที่ออกแบบมาสำหรับ Coroutine ที่ทำงานบน Event Loop

หน้าที่หลัก:

[โค้ด / แผนภาพ : text]
Producer Coroutine
       │
       ▼
asyncio.Queue
       │
       ▼
Consumer Coroutine
[จบโค้ด / แผนภาพ]

คุณสมบัติสำคัญ
--------------

1. เป็น Async Communication Bridge
2. ใช้ส่ง Message/Task ระหว่าง Coroutine
3. ทำงานร่วมกับ Event Loop
4. รองรับ Concurrent Reads/Writes ของ Coroutine
5. ไม่จำเป็นต้องสร้าง Lock เองสำหรับการจัดการ Queue
6. รักษา FIFO

10. Bounded Queue และ Backpressure
==================================

maxsize
------------

สามารถกำหนดขนาด Queue ได้

[โค้ด / แผนภาพ : python]
queue = asyncio.Queue(maxsize=2)

----------------

[โค้ด / แผนภาพ : text]

------------

ใช้รอจนกว่างานทั้งหมดที่ถูกใส่เข้า Queue จะถูกทำเสร็จและเรียก task_done() ครบ

[โค้ด / แผนภาพ : python]

[จบโค้ด / แผนภาพ]

แนวคิด:

[โค้ด / แผนภาพ : text]
put()
 ↓
งานอยู่ใน Queue
 ↓
get()
 ↓
ประมวลผล
 ↓
task_done()
 ↓
งานเสร็จ
[จบโค้ด / แผนภาพ]

เมื่อทุกงานเสร็จ:

[โค้ด / แผนภาพ : text]

[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

โครงสร้างหลัก
-------------

[โค้ด / แผนภาพ : python]
async def producer(queue, total_coupons):
    for i in range(1, total_coupons + 1):
        coupon = f"COUPON-{i:02d}"
        await queue.put(coupon)
        await asyncio.sleep(...)
[จบโค้ด / แผนภาพ]

Consumer:

[โค้ด / แผนภาพ : python]
async def consumer(queue, consumer_name):
    while True:
        coupon = await queue.get()

        if coupon is None:
            queue.task_done()
            break

        # process coupon

        queue.task_done()
[จบโค้ด / แผนภาพ]

ใน main():

[โค้ด / แผนภาพ : python]
queue = asyncio.Queue()

prod_task = asyncio.create_task(
    producer(queue, TOTAL_COUPONS)
)

cons_task = asyncio.create_task(
    consumer(queue, "Consumer_01")
)

await prod_task
await queue.join()

await queue.put(None)
await cons_task
[จบโค้ด / แผนภาพ]

15. สรุปคำสั่งสำคัญ
===================

- คำสั่ง: asyncio.Queue()
  ความหมาย: สร้าง Async Queue

- คำสั่ง: queue.put(x)
  ความหมาย: เพิ่มข้อมูลเข้า Queue

- คำสั่ง: queue.get()
  ความหมาย: ดึงข้อมูลจาก Queue

- คำสั่ง: queue.task_done()
  ความหมาย: แจ้งว่างานที่ get มาเสร็จแล้ว

- คำสั่ง: queue.join()
  ความหมาย: รอจนงานทั้งหมดเสร็จ

- คำสั่ง: asyncio.create_task()
  ความหมาย: สร้าง Task ให้ Event Loop ทำงาน

- คำสั่ง: await asyncio.sleep()
  ความหมาย: รอแบบไม่ Block Event Loop

- คำสั่ง: maxsize
  ความหมาย: จำกัดความจุ Queue

- คำสั่ง: None
  ความหมาย: Sentinel สำหรับสั่ง Consumer หยุด

18. จำแบบสั้นที่สุด 🧠
=====================

Queue = ตัวกลางจัดลำดับงาน

FIFO = เข้าก่อนออกก่อน

Enqueue = เข้า Tail

Dequeue = ออก Head

Producer = สร้างงาน

Consumer = ประมวลผลงาน

asyncio.Queue = Queue สำหรับ Coroutine

get() ตอน Queue ว่าง = await แล้ว Event Loop ไปทำงานอื่น

put() ตอน Queue เต็ม = await → Backpressure

task_done() = งานนี้เสร็จ

join() = รอทุกงานเสร็จ

Multiple Consumers = แบ่งงานเพื่อเพิ่ม Throughput

None = Sentinel สำหรับหยุด Consumer
