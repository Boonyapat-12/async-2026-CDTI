1. Redis คืออะไร
================

Redis คือระบบ In-Memory Data Structure Store

แนวคิดหลักคือ Redis เก็บ Active Data ไว้ใน:

[โค้ด / แผนภาพ : text]
RAM (Main Memory)
[จบโค้ด / แผนภาพ]

แทนการทำงานกับข้อมูลจาก Disk เป็นหลักเหมือนฐานข้อมูลแบบดั้งเดิม

ผลที่ได้
------------

- Latency ต่ำมาก
- ประมวลผลข้อมูลได้เร็ว
- รองรับ Operations จำนวนมาก
- เหมาะกับระบบ Real-Time

2. ทำไม Redis ถึงเร็ว
=====================

2.1 เก็บข้อมูลใน RAM
--------------------

RAM มีความเร็วสูงกว่า Disk และไม่ต้องรอ Disk Seek / Heavy I/O

เอกสารระบุว่า RAM Operations สามารถทำงานในระดับ:

[โค้ด / แผนภาพ : text]
Microseconds
(< 1 ms)
[จบโค้ด / แผนภาพ]

จึงทำให้ Redis มี Sub-Millisecond Latency

----------------------------------------------------------------

2.2 High Throughput
-------------------

Redis สามารถรองรับ:

[โค้ด / แผนภาพ : text]
100,000+ Operations / Second
[จบโค้ด / แผนภาพ]

บน Hardware ระดับหนึ่งได้ตาม Benchmark ที่ระบุในเอกสาร

----------------------------------------------------------------

2.3 Volatile แต่ทำ Persistence ได้
----------------------------------

โดยธรรมชาติ RAM เป็น Memory แบบ Volatile

แต่ Redis มีระบบ Persistence ที่สามารถบันทึกข้อมูลลง Disk ได้ เช่น:

[โค้ด / แผนภาพ : text]
RDB
AOF
[จบโค้ด / แผนภาพ]

ดังนั้น Redis ไม่ได้หมายความว่า:

ข้อมูลจะอยู่เฉพาะใน RAM และหายทั้งหมดเสมอไป

แต่สามารถกำหนดวิธีเก็บข้อมูลลง Disk ได้

5. I/O Multiplexing
===================

แม้ Redis ใช้ Single Thread แต่สามารถดูแล Client Connections จำนวนมากได้ด้วย:

[โค้ด / แผนภาพ : text]
I/O Multiplexing
[จบโค้ด / แผนภาพ]

โดยใช้กลไก เช่น:

[โค้ด / แผนภาพ : text]
epoll
kqueue
[จบโค้ด / แผนภาพ]

แนวคิดคือใช้ Non-Blocking System Calls เพื่อ Monitor Client Sockets จำนวนมากพร้อมกัน

[โค้ด / แผนภาพ : text]
Client 1 ─┐
Client 2 ─┤
Client 3 ─┤
Client 4 ─┼──► Redis Event Loop / I/O
Client N ─┘
[จบโค้ด / แผนภาพ]

ดังนั้น Single Thread ไม่ได้หมายความว่า Redis รองรับ Client ได้เพียงคนเดียว

11. RDB vs AOF
==============

Redis มี Persistence หลักที่เอกสารเน้น 2 แบบ:

[โค้ด / แผนภาพ : text]
RDB
AOF
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

11.1 RDB — Redis Database
-------------------------

RDB สร้าง:

[โค้ด / แผนภาพ : text]
Point-in-Time Snapshot
[จบโค้ด / แผนภาพ]

เป็น Compact Binary Snapshot

ข้อดีตามเอกสาร:

- Recovery เร็ว
- Runtime Performance Impact ต่ำ

ภาพรวม:

[โค้ด / แผนภาพ : text]
Redis Memory
     │
     ▼
 Snapshot
     │
     ▼
   Disk
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

11.2 AOF — Append-Only File
---------------------------

AOF บันทึก:

[โค้ด / แผนภาพ : text]
ทุก Write Operation
[จบโค้ด / แผนภาพ]

แบบ Sequential Log

ข้อดี:

- Data Durability สูง
- กำหนด Sync Interval ได้

ภาพรวม:

[โค้ด / แผนภาพ : text]
WRITE 1 ─┐
WRITE 2 ─┤
WRITE 3 ─┼──► AOF
WRITE 4 ─┘
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

RDB vs AOF จำง่าย
-----------------

- หัวข้อ: รูปแบบ
  RDB: Snapshot
  AOF: Log ทุก Write

- หัวข้อ: Recovery
  RDB: เร็ว
  AOF: เน้นความทนทานของข้อมูล

- หัวข้อ: File
  RDB: Compact Binary
  AOF: Append-Only Log

- หัวข้อ: จุดเด่น
  RDB: Runtime Impact ต่ำ
  AOF: Durability สูง

13. Redis Pub/Sub
=================

Publish–Subscribe Pattern
-------------------------

มี:

[โค้ด / แผนภาพ : text]
Publisher
    │
    ▼
 Channel
    │
    ├──► Subscriber A
    ├──► Subscriber B
    └──► Subscriber C
[จบโค้ด / แผนภาพ]

Publisher ไม่จำเป็นต้องรู้ว่า Subscriber คือใคร

คำสั่งสำคัญ:

[โค้ด / แผนภาพ : text]
PUBLISH channel message

SUBSCRIBE channel

PSUBSCRIBE pattern*
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

จุดสำคัญที่สุด: At-Most-Once
----------------------------

Redis Pub/Sub เป็น:

At-most-once delivery

หรือในเอกสารเรียกว่า:

Fire-and-Forget

ถ้า Subscriber Offline ตอนที่ Message ถูก Publish:

[โค้ด / แผนภาพ : text]
Message
   ↓
Subscriber Offline
   ↓
❌ Message หาย
[จบโค้ด / แผนภาพ]

ไม่มี Message History ให้ย้อนกลับมาอ่าน

15. Consumer Groups
===================

Consumer Groups ใช้เมื่อมี Consumer หลายตัวช่วยกันประมวลผล Stream

[โค้ด / แผนภาพ : text]
             Redis Stream
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   Consumer 1          Consumer 2
[จบโค้ด / แผนภาพ]

แต่ละ Message สามารถถูกส่งไปยัง Consumer ที่แตกต่างกันภายใน Group

----------------------------------------------------------------

Load Balancing
--------------

Consumer หลายตัว:

[โค้ด / แผนภาพ : text]
Consumer 1 → งาน A
Consumer 2 → งาน B
Consumer 3 → งาน C
[จบโค้ด / แผนภาพ]

ช่วยแบ่งภาระการประมวลผล

----------------------------------------------------------------

At-Least-Once Delivery
----------------------

Consumer ต้อง Acknowledge Message ด้วย:

[โค้ด / แผนภาพ : text]
XACK
[จบโค้ด / แผนภาพ]

แนวคิด:

[โค้ด / แผนภาพ : text]
รับ Message
     ↓
ประมวลผล
     ↓
XACK
     ↓
ถือว่างานถูก Acknowledge
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

Pending Entries List — PEL
--------------------------

Redis จะติดตาม Message ที่ยังไม่ได้รับการ Acknowledge

เรียกว่า:

[โค้ด / แผนภาพ : text]
Pending Entries List (PEL)
[จบโค้ด / แผนภาพ]

มีประโยชน์เมื่อ Consumer Crash เพราะสามารถติดตามงานที่ยังค้างอยู่ได้

16. เปรียบเทียบ Pub/Sub กับ Streams
===================================

นี่คือหัวข้อที่ควรจำมากที่สุด ⭐

- หัวข้อ: แนวคิด
  Redis Pub/Sub: Fire-and-Forget
  Redis Streams: Persistent Event Stream

- หัวข้อ: การเก็บ Message
  Redis Pub/Sub: ❌ ไม่มี History
  Redis Streams: ✅ เก็บ Message

- หัวข้อ: Offline Consumer
  Redis Pub/Sub: ❌ พลาดแล้วหาย
  Redis Streams: ✅ อ่านย้อนหลังได้

- หัวข้อ: Replay
  Redis Pub/Sub: ❌ ไม่ได้
  Redis Streams: ✅ ได้

- หัวข้อ: Delivery
  Redis Pub/Sub: At-Most-Once
  Redis Streams: รองรับ At-Least-Once ผ่าน Consumer Groups

- หัวข้อ: Consumer Groups
  Redis Pub/Sub: ❌
  Redis Streams: ✅

- หัวข้อ: Acknowledge
  Redis Pub/Sub: ❌
  Redis Streams: ✅ XACK

- หัวข้อ: เหมาะกับ
  Redis Pub/Sub: Real-Time Broadcast
  Redis Streams: Event Processing


จำสั้น ๆ
------------

[โค้ด / แผนภาพ : text]
Pub/Sub
= เร็ว + สด + ไม่เก็บ

Streams
= เก็บ + ย้อนอ่าน + ประมวลผลเป็นระบบ
[จบโค้ด / แผนภาพ]

22. ตารางจำเร็ว
===============

- คำศัพท์: Redis
  จำว่า: In-Memory Data Structure Store

- คำศัพท์: RAM
  จำว่า: Storage หลักของ Active Data

- คำศัพท์: Sub-Millisecond
  จำว่า: Latency ต่ำกว่า 1 ms

- คำศัพท์: String
  จำว่า: Text / Number / Binary / Counter

- คำศัพท์: Hash
  จำว่า: Field–Value

- คำศัพท์: List
  จำว่า: Linked List / Queue / Stack

- คำศัพท์: Set
  จำว่า: Unique / Unordered

- คำศัพท์: Sorted Set
  จำว่า: Sort ตาม Score

- คำศัพท์: Stream
  จำว่า: Append-Only Log

- คำศัพท์: Pub/Sub
  จำว่า: Fire-and-Forget

- คำศัพท์: At-Most-Once
  จำว่า: พลาดแล้วไม่ส่งซ้ำ

- คำศัพท์: Stream
  จำว่า: Persistent / Replayable

- คำศัพท์: Consumer Group
  จำว่า: แบ่งงานหลาย Consumer

- คำศัพท์: XACK
  จำว่า: Acknowledge Message

- คำศัพท์: PEL
  จำว่า: Pending Entries List

- คำศัพท์: RDB
  จำว่า: Snapshot

- คำศัพท์: AOF
  จำว่า: Append-Only Write Log

- คำศัพท์: Cache
  จำว่า: เก็บ Hot Data

- คำศัพท์: Rate Limiting
  จำว่า: จำกัด Request

- คำศัพท์: I/O Multiplexing
  จำว่า: จัดการ Socket จำนวนมาก

23. จำแบบสั้นที่สุด 🧠
=====================

Redis = RAM + Data Structures + Speed

Redis เร็วเพราะ Active Data อยู่ใน RAM

Single Thread ไม่ได้แปลว่ารับ Client ได้คนเดียว

I/O Multiplexing = จัดการ Connections จำนวนมาก

Pub/Sub = ส่งทันที แต่ไม่เก็บ

Pub/Sub = At-Most-Once

Streams = เก็บ Event และ Replay ได้

Consumer Groups = แบ่งงานกันประมวลผล

XACK = ยืนยันว่า Process แล้ว

PEL = ติดตาม Message ที่ยังไม่ Acknowledge

RDB = Snapshot

AOF = Log ทุก Write

Cache = ลดภาระ Database
