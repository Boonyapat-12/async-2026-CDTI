บท 1 — พื้นฐาน Asynchronous Programming
========================================================================

[BASE-01] ภาพใหญ่: ทำไมต้อง Async?
โปรแกรมที่รอเครือข่าย ฐานข้อมูล หรือเวลาจำลอง มักมีช่วงที่ CPU ยังทำงานอื่นได้
Async ช่วยให้งานอื่นเดินต่อระหว่างรอ โดยต้องใช้คำสั่งและไลบรารีที่รองรับ
การใส่ async def อย่างเดียวไม่ได้เปลี่ยนโค้ด blocking ให้ไม่บล็อก

คำศัพท์ที่ต้องแยก
- Synchronous: ทำขั้นตอนตามลำดับ ผู้เรียกต้องรอขั้นตอนนั้นคืนการควบคุม
- Asynchronous: จัดการงานที่ยังไม่เสร็จ และกลับมาทำต่อเมื่อพร้อม
- Concurrency: หลายงานมีช่วงชีวิตทับซ้อนกัน อาจสลับทำบน CPU เดียว
- Parallelism: หลายงานประมวลผลพร้อมกันจริง เช่นหลาย process บนหลาย core
- I/O-bound: เวลาส่วนใหญ่รอข้อมูล เหมาะกับ async I/O หรือ thread
- CPU-bound: เวลาส่วนใหญ่คำนวณ Python ล้วน มักพิจารณาหลาย process

[BASE-02] เลือกวิธีทำงาน
งานสั้นตามลำดับ -> synchronous อ่านและตรวจง่าย
รอ HTTP จำนวนมาก -> asyncio + async HTTP client
ไลบรารี I/O แบบ blocking -> thread หรือ asyncio.to_thread()
งานคำนวณ Python หนัก -> process; อย่าสรุปว่า asyncio ทำให้เร็วเสมอ
thread แชร์หน่วยความจำใน process; process แยกหน่วยความจำตามปกติ
GIL ใน CPython แบบปกติจำกัดการรัน Python bytecode หลาย thread พร้อมกัน
แต่ไม่ควรเหมารวมทุก Python build หรือ native library ว่ามีพฤติกรรมเดียวกัน

[BASE-03] ประมาณเวลา
await job(1); await job(2) -> เวลารอรวมใกล้ 3 วินาที
gather(job(1), job(2)) -> เวลารอใกล้ 2 วินาที เมื่อเป็นงานรออิสระ
เวลาจริงยังมี overhead การจัดตาราง network และข้อจำกัดบริการ
ใช้ time.perf_counter() วัดช่วงเวลา; time.time() ใช้เวลาแบบนาฬิกาปฏิทิน

ตัวอย่างจาก repo
Week1/coffee01_synchronous.py เทียบ coffee04_asyncio.py
Week1/up01_synchronous.py เทียบ up02_thread.py, up03_multiprocess.py,
up04_asyncio.py: สังเกต shared state และการรอ มากกว่าดูเวลารวมอย่างเดียว
Week2/restaurant_01_*.py: ลำดับภายในลูกค้าแต่ละคนยังต้องถูกต้อง
Week6/robots.py: reset โรงงานก่อน แล้วรัน workflow ของแต่ละ robot ร่วมกัน

แนวตอบข้อเขียน
"Async เหมาะกับงานที่รอ I/O เพราะ coroutine คืนการควบคุมระหว่างรอ
event loop จึงเดินงานที่พร้อมต่อได้ Concurrency นี้ไม่รับประกัน Parallelism
และจะเสียประโยชน์ถ้าใช้ blocking call บน thread ของ event loop"

ข้อผิดพลาดที่พบบ่อย
- ใช้ time.sleep() ใน async def -> บล็อก thread ที่เรียกมัน
- เรียก coroutine แต่ไม่ await / schedule -> ยังไม่ทำงาน
- งานสัมพันธ์กันแต่ gather พร้อมกัน -> ลำดับธุรกิจอาจผิด

2.1 time
------------

[โค้ด / แผนภาพ : python]
from time import sleep, ctime, time, process_time
[จบโค้ด / แผนภาพ]

- ชื่อ: sleep(5)
  ใช้ทำอะไร: หยุดรอแบบ blocking 5 วินาที
  ตัวอย่าง: ใช้ใน synchronous/thread/process

- ชื่อ: ctime()
  ใช้ทำอะไร: แปลงเวลาปัจจุบันเป็นข้อความอ่านง่าย
  ตัวอย่าง: Wed Jun 24 11:16:05 2026

- ชื่อ: time()
  ใช้ทำอะไร: จับเวลาจริงแบบ wall time
  ตัวอย่าง: เวลาที่ผู้ใช้รอจริง

- ชื่อ: process_time()
  ใช้ทำอะไร: จับเวลาที่ CPU ใช้จริง
  ตัวอย่าง: ไม่นับเวลานอน sleep() เป็นหลัก


ใน pid ใช้ sleep, ctime, time
ใน ps เพิ่ม process_time เพื่อดู CPU Time

2.2 os
------------

[โค้ด / แผนภาพ : python]
import os
[จบโค้ด / แผนภาพ]

ใช้ดู Process ID ของโปรแกรม:

[โค้ด / แผนภาพ : python]
pid = os.getpid()
[จบโค้ด / แผนภาพ]

PID คือเลขประจำ process

- Synchronous: ทุกงานอยู่ PID เดียว
- Multi-thread: ทุก thread ยังอยู่ PID เดียวกัน
- Multi-processing: แต่ละ process จะมี PID คนละเลข
- Asyncio: ทุก task อยู่ PID เดียวกัน

2.3 threading
-------------

[โค้ด / แผนภาพ : python]
import threading
[จบโค้ด / แผนภาพ]

ใช้ดูข้อมูล thread ปัจจุบัน:

[โค้ด / แผนภาพ : python]
thread_id = threading.current_thread().native_id
thread_name = threading.current_thread().name
[จบโค้ด / แผนภาพ]

และใช้สร้าง Thread ใน pid02 / ps02:

[โค้ด / แผนภาพ : python]
t = threading.Thread(
    target=make_coffee,
    args=(customer,),
    name=f"Thread-{customer}"
)
t.start()
t.join()
[จบโค้ด / แผนภาพ]

คำสำคัญ:

- คำสั่ง: Thread(...)
  ความหมาย: สร้าง thread ใหม่

- คำสั่ง: target=make_coffee
  ความหมาย: ให้ thread ไปทำฟังก์ชันนี้

- คำสั่ง: args=(customer,)
  ความหมาย: ส่ง argument เข้า function ต้องมี comma เพราะเป็น tuple

- คำสั่ง: name=...
  ความหมาย: ตั้งชื่อ thread ให้อ่าน log ง่าย

- คำสั่ง: start()
  ความหมาย: เริ่มทำงานจริง

- คำสั่ง: join()
  ความหมาย: รอให้ thread ทำงานเสร็จก่อนค่อยไปต่อ

2.4 multiprocessing
-------------------

[โค้ด / แผนภาพ : python]
import multiprocessing
[จบโค้ด / แผนภาพ]

ใช้สร้าง process แยกจริง ๆ:

[โค้ด / แผนภาพ : python]
p = multiprocessing.Process(
    target=make_coffee,
    args=(customer,)
)
p.start()
p.join()
[จบโค้ด / แผนภาพ]

สิ่งสำคัญ: process แต่ละตัวมี memory แยกกัน ไม่แชร์ตัวแปรธรรมดากันโดยตรง

ถ้าจะส่งข้อมูลจาก process ลูกกลับมาที่ process หลัก ใช้ multiprocessing.Queue():

[โค้ด / แผนภาพ : python]
result_queue = multiprocessing.Queue()
result_queue.put((mem_mb, cpu_duration))
mem, cpu_t = result_queue.get()
[จบโค้ด / แผนภาพ]

ไอริสใช้ pattern นี้ใน ps03_multiprocess.py เพื่อรวม RAM/CPU จาก process ย่อยค่ะ

2.5 asyncio
------------

[โค้ด / แผนภาพ : python]
import asyncio
[จบโค้ด / แผนภาพ]

ใช้เขียน asynchronous programming แบบ event loop

คำสำคัญ:

- คำสั่ง: async def
  ความหมาย: ประกาศ coroutine function

- คำสั่ง: await
  ความหมาย: ยอมคืน control ให้ event loop ระหว่างรอ

- คำสั่ง: asyncio.sleep(5)
  ความหมาย: รอแบบ non-blocking

- คำสั่ง: asyncio.create_task(...)
  ความหมาย: แปลง coroutine เป็น task ที่ event loop จัดการ

- คำสั่ง: asyncio.gather(*tasks)
  ความหมาย: รอหลาย task พร้อมกัน

- คำสั่ง: asyncio.run(main())
  ความหมาย: เริ่ม event loop


ตัวอย่างจาก pid04 / ps04:

[โค้ด / แผนภาพ : python]
coro = make_coffee(customer)
task = asyncio.create_task(coro, name=f"Task-{customer}")
tasks.append(task)
await asyncio.gather(*tasks)
[จบโค้ด / แผนภาพ]

3.1 pid01_synchronous.py
------------------------

แนวคิด: ทำทีละคนตามคิว

สิ่งที่ไอริสเขียน:

[โค้ด / แผนภาพ : python]
queue = ['A', 'B', 'C']
for customer in queue:
    make_coffee(customer)
[จบโค้ด / แผนภาพ]

ผลที่ควรเข้าใจ:

- ลูกค้า A เสร็จก่อน แล้วค่อย B แล้วค่อย C
- ใช้ thread เดียวคือ MainThread
- ใช้ PID เดียวและ TID เดียว
- ถ้าแต่ละคน sleep(5) รวม 3 คน จะใช้เวลาประมาณ 15 วินาที

ตัวแปรสำคัญ:

- ตัวแปร: queue
  ความหมาย: รายชื่อลูกค้าในคิว

- ตัวแปร: pid
  ความหมาย: Process ID ของโปรแกรม

- ตัวแปร: thread_id
  ความหมาย: Thread ID ปัจจุบัน

- ตัวแปร: thread_name
  ความหมาย: ชื่อ Thread ปัจจุบัน

- ตัวแปร: start_time
  ความหมาย: เวลาเริ่มต้น

- ตัวแปร: duration
  ความหมาย: เวลารวมที่ใช้จริง

3.2 pid02_thread.py
-------------------

แนวคิด: สร้าง thread 1 ตัวต่อลูกค้า 1 คน

สิ่งที่ไอริสเขียน:

[โค้ด / แผนภาพ : python]
threads = []
for customer in queue:
    t = threading.Thread(target=make_coffee, args=(customer,), name=f"Thread-{customer}")
    threads.append(t)
    t.start()

for t in threads:
    t.join()
[จบโค้ด / แผนภาพ]

ผลที่ควรเข้าใจ:

- A, B, C เริ่มชงใกล้ ๆ กัน
- PID เหมือนกัน เพราะยังอยู่ process เดียว
- TID ต่างกัน เพราะเป็นคนละ thread
- เวลารวมประมาณ 5 วินาที เพราะรอพร้อมกัน

ข้อควรระวังสำหรับ Lab up02:

ถ้ามีตัวแปรร่วม เช่น cup_number หลาย thread อาจแก้พร้อมกันจนค่าเพี้ยนได้ เรียกว่า race
condition ค่ะ

ถ้าต้องกันค่าเพี้ยน ใช้ threading.Lock():

[โค้ด / แผนภาพ : python]
lock = threading.Lock()

with lock:
    cup_number += 1
[จบโค้ด / แผนภาพ]

3.3 pid03_multiprocess.py
-------------------------

แนวคิด: สร้าง process 1 ตัวต่อลูกค้า 1 คน

สิ่งที่ไอริสเขียน:

[โค้ด / แผนภาพ : python]
processes = []
for customer in queue:
    p = multiprocessing.Process(target=make_coffee, args=(customer,))
    processes.append(p)
    p.start()

for p in processes:
    p.join()
[จบโค้ด / แผนภาพ]

ผลที่ควรเข้าใจ:

- A, B, C ทำงานพร้อมกันใน process แยก
- PID ต่างกัน เพราะเป็นคนละ process
- Thread Name มักเป็น MainThread ในแต่ละ process
- เวลารวมประมาณ 5 วินาที

ข้อควรระวังสำหรับ Lab up03:

ตัวแปรธรรมดาไม่แชร์กันระหว่าง process เช่น ถ้ามี:

[โค้ด / แผนภาพ : python]
cup_number = 0
[จบโค้ด / แผนภาพ]

แล้ว process ลูกแต่ละตัวเพิ่มค่าเอง ค่าใน main process จะไม่เปลี่ยนตามโดยอัตโนมัติ

ถ้าต้องส่งค่ากลับ main process ใช้:

- multiprocessing.Queue()
- multiprocessing.Value()
- multiprocessing.Manager()

3.4 pid04_asyncio.py
--------------------

แนวคิด: ใช้ task หลายตัวใน thread เดียว process เดียว แต่สลับงานระหว่างรอ

[โค้ด / แผนภาพ : python]
tasks = []

await asyncio.gather(*tasks)
[จบโค้ด / แผนภาพ]

ใน make_coffee() ใช้:

[โค้ด / แผนภาพ : python]
await asyncio.sleep(5)
[จบโค้ด / แผนภาพ]

ผลที่ควรเข้าใจ:

- PID เดียวกัน
- TID เดียวกัน
- Task ID ต่างกัน
- เหมาะกับงานรอ เช่น network, file, sleep, API
- ถ้าใช้ await asyncio.sleep(5) หลาย task จะรอพร้อมกันได้ ใช้เวลาประมาณ 5 วินาที

4. ไอริสทำอะไรในชุด ps01-04
---------------------------

ชุด ps คือเอา logic จาก pid มาเพิ่มการวัด performance:

1. วัดเวลาจริงด้วย time()
2. วัด CPU Time ด้วย process_time()
3. วัด RAM ด้วย psutil
4. เพิ่มงานจำลอง CPU-bound ด้วย sum(i * i for i in range(1000000))

----------------------------------------------------------------

4.1 ตัวแปรที่เพิ่มใน ps
-----------------------

- ตัวแปร: start_cpu
  ใช้ทำอะไร: เวลา CPU ตอนเริ่ม

- ตัวแปร: cpu_duration
  ใช้ทำอะไร: เวลา CPU ที่ใช้จริง

- ตัวแปร: process
  ใช้ทำอะไร: object ของ process ปัจจุบันจาก psutil

- ตัวแปร: mem_mb
  ใช้ทำอะไร: RAM ที่ใช้ หน่วย MB

- ตัวแปร: main_mem
  ใช้ทำอะไร: RAM ของ main process

- ตัวแปร: child_memories
  ใช้ทำอะไร: RAM ของ process ลูกทั้งหมด

- ตัวแปร: child_cpu_times
  ใช้ทำอะไร: CPU Time ของ process ลูกทั้งหมด

- ตัวแปร: total_memory
  ใช้ทำอะไร: RAM รวม main + ลูก

- ตัวแปร: total_cpu_time
  ใช้ทำอะไร: CPU Time รวม main + ลูก


----------------------------------------------------------------

4.2 ทำไมต้องมี sum(i * i for i in range(1000000))
-------------------------------------------------

บรรทัดนี้จำลองงานคำนวณเล็ก ๆ:

[โค้ด / แผนภาพ : python]
sum(i * i for i in range(1000000))
[จบโค้ด / แผนภาพ]

เหตุผล:

- ถ้ามีแต่ sleep(5) โปรแกรมแทบไม่ได้ใช้ CPU
- พอใส่ sum(...) จะเห็น CPU Time เพิ่มขึ้นบ้าง
- ช่วยแยกความต่างระหว่าง “เวลาที่รอจริง” กับ “เวลาที่ CPU ทำงานจริง”

4.3 ต่างกันยังไงระหว่าง Wall Time กับ CPU Time
----------------------------------------------

- เวลา: Wall Time
  ความหมาย: เวลาที่คนรอจริงตั้งแต่เริ่มถึงจบ
  ตัวอย่าง: Synchronous 3 คน × 5 วิ = ประมาณ 15 วิ

- เวลา: CPU Time
  ความหมาย: เวลาที่ CPU ใช้คิดจริง
  ตัวอย่าง: อาจน้อยกว่า wall time มาก เพราะ sleep() ไม่ได้ใช้ CPU


ตัวอย่าง:

[โค้ด / แผนภาพ : python]
start_time = time()
start_cpu = process_time()

# ทำงาน

duration = time() - start_time
cpu_duration = process_time() - start_cpu
[จบโค้ด / แผนภาพ]

5. เอาไปใช้กับ Lab up01-04 ยังไง

cup_number = 0

6. แนวทางทำ up01_synchronous.py
-------------------------------

เป้าหมาย
------------

ทำทีละคนตามลำดับ ไม่มีงานพร้อมกัน

Pattern จาก pid01
-----------------

[โค้ด / แผนภาพ : python]
for customer in queue:
    make_coffee(customer)
[จบโค้ด / แผนภาพ]

วิธีคิดสำหรับ up01
------------------

1. สร้างตัวแปร global เช่น cup_number = 0
2. ใน update_cup_number() เพิ่มเลขแก้วทีละ 1
3. ใน make_coffee() เรียก update_cup_number(customer_name) แล้วจำลองชงกาแฟด้วย sleep(5)
4. ใน main() loop ลูกค้า A, B, C ทีละคน

สิ่งที่ควรเห็น
--------------

- เลขแก้วควรเรียง 1, 2, 3 เสมอ
- เวลารวมประมาณ 15 วินาที
- ไม่มี race condition เพราะทำทีละคน

7. แนวทางทำ up02_thread.py
--------------------------

เป้าหมาย
------------

ทำพร้อมกันด้วย Thread

Pattern จาก pid02
-----------------

[โค้ด / แผนภาพ : python]
threads = []
for customer in queue:
    t = threading.Thread(target=make_coffee, args=(customer,), name=f"Thread-{customer}")
    threads.append(t)
    t.start()

for t in threads:
    t.join()
[จบโค้ด / แผนภาพ]

จุดที่ต้องระวัง
---------------

ถ้า update_cup_number() แก้ cup_number พร้อมกันหลาย thread อาจเกิด race condition

ตัวอย่างปัญหา:

[โค้ด / แผนภาพ : python]
old = cup_number
sleep(0.1)
cup_number = old + 1
[จบโค้ด / แผนภาพ]

ถ้าหลาย thread อ่านค่าเก่าพร้อมกัน อาจได้เลขซ้ำ

วิธีแก้ถ้าต้องการให้เลขถูก
--------------------------

ใช้ lock:

[โค้ด / แผนภาพ : python]
lock = threading.Lock()

with lock:
    cup_number += 1
[จบโค้ด / แผนภาพ]

สิ่งที่ควรเห็น
--------------

- เวลาโดยรวมประมาณ 5 วินาที
- ถ้าไม่ใช้ lock อาจเห็นเลขแก้วเพี้ยน/ซ้ำในบางรอบ
- ถ้าใช้ lock เลขแก้วควรถูกต้องขึ้น

----------------------------------------------------------------

8. แนวทางทำ up03_multiprocess.py
--------------------------------

เป้าหมาย
------------

ทำพร้อมกันด้วย Process

Pattern จาก pid03
-----------------

[โค้ด / แผนภาพ : python]
processes = []
for customer in queue:
    p = multiprocessing.Process(target=make_coffee, args=(customer,))
    processes.append(p)
    p.start()

for p in processes:
    p.join()
[จบโค้ด / แผนภาพ]

จุดที่ต้องระวังมากที่สุด
------------------------

Process ไม่แชร์ memory ธรรมดากัน

ถ้าเขียนแบบนี้:

[โค้ด / แผนภาพ : python]
cup_number = 0
[จบโค้ด / แผนภาพ]

แต่ละ process จะมี cup_number เป็นของตัวเอง ทำให้ main process ไม่รู้ว่าลูกทำอะไรไปแล้ว

วิธีแชร์ข้อมูลระหว่าง process
-----------------------------

เลือกใช้ได้ตามโจทย์:

- วิธี: multiprocessing.Queue()
  ใช้เมื่อไหร่: ส่งผลลัพธ์จาก process ลูกกลับ main

- วิธี: multiprocessing.Value()
  ใช้เมื่อไหร่: แชร์ค่าตัวเลขเดียว เช่น counter

- วิธี: multiprocessing.Manager().dict/list()
  ใช้เมื่อไหร่: แชร์ dict/list


ตัวอย่าง Queue:

[โค้ด / แผนภาพ : python]
result_queue = multiprocessing.Queue()

p = multiprocessing.Process(target=make_coffee, args=(customer, result_queue))

# ใน process ลูก
result_queue.put((customer_name, cup_no))

# ใน main process
customer_name, cup_no = result_queue.get()
[จบโค้ด / แผนภาพ]

สิ่งที่ควรเห็น
--------------

- PID ของลูกค้าแต่ละคนต่างกัน
- เวลารวมประมาณ 5 วินาที
- ถ้าต้องรวมผลลัพธ์ ต้องส่งกลับมาผ่าน Queue หรือ shared object

9. แนวทางทำ up04_asyncio.py
---------------------------

เป้าหมาย
------------

ทำพร้อมกันแบบ async task ใน process/thread เดียว

สิ่งที่ไฟล์ up04 ต้องมีเพิ่ม
----------------------------

ตอนนี้ up04_asyncio.py ยังไม่มี import ในไฟล์ตั้งต้น ดังนั้นควรมีอย่างน้อย:

[โค้ด / แผนภาพ : python]
from time import ctime, time
import asyncio
[จบโค้ด / แผนภาพ]

ถ้าจะดู PID/TID แบบ pid04 ให้เพิ่ม:

[โค้ด / แผนภาพ : python]
import os
import threading
[จบโค้ด / แผนภาพ]

Pattern จาก pid04
-----------------

[โค้ด / แผนภาพ : python]
tasks = []
for customer in queue:
    coro = make_coffee(customer)
    task = asyncio.create_task(coro, name=f"Task-{customer}")
    tasks.append(task)

await asyncio.gather(*tasks)
[จบโค้ด / แผนภาพ]

ใน async function ใช้:

[โค้ด / แผนภาพ : python]
await asyncio.sleep(5)
[จบโค้ด / แผนภาพ]

ห้ามใช้ sleep(5) ธรรมดาใน async function ถ้าอยากให้ task สลับกันได้ เพราะ sleep(5) จะ
block event loop

ถ้ามี update_cup_number() แบบ async
-----------------------------------

[โค้ด / แผนภาพ : python]
async def update_cup_number(customer_name):
    global cup_number
    cup_number += 1
    print(f"ลูกค้า {customer_name} ได้แก้วหมายเลข {cup_number}")
[จบโค้ด / แผนภาพ]

ถ้าต้องป้องกันช่วง critical section ใน asyncio ใช้:

[โค้ด / แผนภาพ : python]
lock = asyncio.Lock()

async with lock:
    cup_number += 1
[จบโค้ด / แผนภาพ]

สิ่งที่ควรเห็น
--------------

- PID เดียวกัน
- TID เดียวกัน
- Task Name ต่างกัน เช่น Task-A, Task-B, Task-C
- เวลารวมประมาณ 5 วินาที ถ้าใช้ await asyncio.sleep(5)

10. ตารางเปรียบเทียบ 4 วิธี
---------------------------

- วิธี: Synchronous
  ทำพร้อมกันไหม: ไม่พร้อมกัน
  PID: เดียว
  Thread ID: เดียว
  เหมาะกับงานแบบไหน: งานง่าย/ทำทีละขั้น
  เวลาประมาณในตัวอย่าง: 15 วิ

- วิธี: Multi-Thread
  ทำพร้อมกันไหม: พร้อมกัน
  PID: เดียว
  Thread ID: หลาย TID
  เหมาะกับงานแบบไหน: งานรอ I/O เช่น sleep/network
  เวลาประมาณในตัวอย่าง: 5 วิ

- วิธี: Multi-processing
  ทำพร้อมกันไหม: พร้อมกัน
  PID: หลาย PID
  Thread ID: แต่ละ process มี MainThread
  เหมาะกับงานแบบไหน: งาน CPU หนัก
  เวลาประมาณในตัวอย่าง: 5 วิ

- วิธี: Asyncio
  ทำพร้อมกันไหม: พร้อมกันแบบสลับ task
  PID: เดียว
  Thread ID: เดียว
  เหมาะกับงานแบบไหน: งาน I/O / wait เยอะ
  เวลาประมาณในตัวอย่าง: 5 วิ

  ใน Lab นี้คือ: simple version

- คำ: concurrent
  ความหมายง่าย ๆ: หลายงานคืบหน้าในช่วงเวลาเดียวกัน
  ใน Lab นี้คือ: thread/process/asyncio version

- คำ: blocking
  ความหมายง่าย ๆ: รอแล้วหยุดการทำงานตรงนั้น
  ใน Lab นี้คือ: sleep(1)

- คำ: non-blocking
  ความหมายง่าย ๆ: รอแล้วให้ระบบไปทำงานอื่นก่อนได้
  ใน Lab นี้คือ: await asyncio.sleep(1)

- คำ: thread
  ความหมายง่าย ๆ: เส้นทางการทำงานย่อยใน process เดียว
  ใน Lab นี้คือ: threading.Thread(...)

- คำ: process
  ความหมายง่าย ๆ: โปรแกรมย่อยแยก memory กัน
  ใน Lab นี้คือ: multiprocessing.Process(...)

- คำ: coroutine
  ความหมายง่าย ๆ: function แบบ async ที่ await ได้
  ใน Lab นี้คือ: async def ...

- คำ: task
  ความหมายง่าย ๆ: coroutine ที่ถูกส่งให้ event loop จัดการ
  ใน Lab นี้คือ: asyncio.create_task(...)

- คำ: join
  ความหมายง่าย ๆ: รอ thread/process ให้ทำงานเสร็จ
  ใน Lab นี้คือ: t.join() / p.join()

- คำ: await
  ความหมายง่าย ๆ: รอ async operation ให้เสร็จ
  ใน Lab นี้คือ: await task

8.4 Function customer_private_workflow(customer)
------------------------------------------------

[โค้ด / แผนภาพ : python]
async def customer_private_workflow(customer):
    print(f"{ctime()} [Task-{customer}] Taking Order ...")
    await asyncio.sleep(1)
    print(f"{ctime()} [Task-{customer}] Taking Order ...Done!")

    print(f"{ctime()} [Task-{customer}] Cooking Spaghetti ...")
    await asyncio.sleep(1)
    print(f"{ctime()} [Task-{customer}] Cooking Spaghetti ...Done!")

    print(f"{ctime()} [Task-{customer}] Manage bar for Drink ...")
    await asyncio.sleep(1)
    print(f"{ctime()} [Task-{customer}] Manage bar for Drink ...Done!")

    print(f"\n{ctime()} [Task-{customer}] All served!")
[จบโค้ด / แผนภาพ]

จุดที่ควรรู้:

- แต่ละลูกค้าเป็น coroutine แยกกัน
- แต่ละจุด await asyncio.sleep(1) คือจุดที่ event loop สามารถสลับไปทำ task อื่นได้
- label [Task-A], [Task-B], [Task-C] ไม่ได้มาจากชื่อ task จริง แต่เขียนจากค่า customer
  ใน f-string

8.5 จุดสำคัญใน main()
---------------------

[โค้ด / แผนภาพ : python]
tasks = []

for customer in customers:
    task = asyncio.create_task(customer_private_workflow(customer))
    tasks.append(task)

for task in tasks:
    await task
[จบโค้ด / แผนภาพ]

อธิบายทีละส่วน:

- บรรทัด: tasks = []
  ความหมาย: list เก็บ task ทั้งหมด

- บรรทัด: asyncio.create_task(...)
  ความหมาย: ส่ง coroutine ให้ event loop เริ่มจัดการ

- บรรทัด: tasks.append(task)
  ความหมาย: เก็บ task ไว้รอทีหลัง

- บรรทัด: for task in tasks: await task
  ความหมาย: รอ task ทุกตัวให้เสร็จ


ถึงจะ await ทีละ task ใน loop แต่เพราะ task ทั้งหมดถูก create_task ก่อนแล้ว งานจึงเริ่ม
concurrent ได้ค่ะ

9. เปรียบเทียบ Thread vs Process vs Asyncio ใน Lab นี้
------------------------------------------------------

- เรื่อง: สร้างด้วย
  Thread: threading.Thread
  Process: multiprocessing.Process
  Asyncio: asyncio.create_task

- เรื่อง: รอด้วย
  Thread: join()
  Process: join()
  Asyncio: await หรือ gather()

- เรื่อง: ใช้ memory
  Thread: process เดียวกัน
  Process: แยก process/memory
  Asyncio: process/thread เดียวโดยทั่วไป

- เรื่อง: เหมาะกับ
  Thread: งานรอ I/O
  Process: งาน CPU หนัก
  Asyncio: งานรอ I/O จำนวนมาก

- เรื่อง: overhead
  Thread: ปานกลาง
  Process: สูงกว่า
  Asyncio: ต่ำกว่า

- เรื่อง: ใน Lab นี้
  Thread: ทำพร้อมกันหลัง greeting
  Process: ทำพร้อมกันหลัง greeting
  Asyncio: สลับ task หลัง greeting

12. Common Mistakes ที่ต้องระวัง
--------------------------------

12.1 ลืม join() ใน thread/process
---------------------------------

ถ้าไม่ join:

[โค้ด / แผนภาพ : python]
for t in processes:
    t.join()
[จบโค้ด / แผนภาพ]

main program อาจจบก่อนงานลูกเสร็จ หรือเวลา total อาจไม่สะท้อนงานจริง

----------------------------------------------------------------

12.2 ลืม await ใน asyncio
-------------------------

ผิด:

[โค้ด / แผนภาพ : python]
greet_diners(customer)
[จบโค้ด / แผนภาพ]

ถูก:

[โค้ด / แผนภาพ : python]
await greet_diners(customer)
[จบโค้ด / แผนภาพ]

ถ้าลืม await จะได้ coroutine object แต่ไม่รันจริง

----------------------------------------------------------------

12.3 ใช้ time.sleep() ใน async function
---------------------------------------

ผิด:

[โค้ด / แผนภาพ : python]
async def customer_private_workflow(customer):
    sleep(1)
[จบโค้ด / แผนภาพ]

ถึงจะรันได้ถ้า import มา แต่จะ block event loop ทำให้ task อื่นไม่ได้ทำงานระหว่างรอ

ถูก:

[โค้ด / แผนภาพ : python]
await asyncio.sleep(1)
[จบโค้ด / แผนภาพ]

----------------------------------------------------------------

12.4 เข้าใจผิดว่า multiprocessing output ต้องเรียงเสมอ
------------------------------------------------------

process ทำงานแยกกัน ดังนั้น output อาจสลับ ไม่เรียง A/B/C เสมอค่ะ

นี่ไม่ใช่ error ถ้า logic ถูกและทุก process join() ครบ
