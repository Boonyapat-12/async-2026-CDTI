บท 3 — Task, Gather, Wait, Timeout และ Cancellation
========================================================================

[TASK-01] Task lifecycle
create_task(coro) -> pending/running -> finished หรือ cancelled
done() ตรวจว่าจบแล้วหรือยัง รวมกรณี cancelled
result() อ่านค่าหลังจบ; ก่อนจบเกิด InvalidStateError
exception() อ่าน exception หลังจบ; task ที่ cancelled ทำให้เกิด CancelledError
get_name()/set_name() ช่วยแยกงาน; เก็บ reference ของ background task
add_done_callback(fn) เรียก callback เมื่อจบ โดย callback รับ Task

[GATHER-01] อยากได้ผลทั้งหมด
await gather(a(), b()) คืนผลตามลำดับ input ไม่ใช่ลำดับเสร็จ
ค่าเริ่มต้น: exception แรกถูกส่งให้ผู้รอ งานอื่นไม่ถูก cancel โดยอัตโนมัติ
return_exceptions=True เก็บ exception ไว้ใน list ผลลัพธ์ ต้องตรวจแต่ละตำแหน่ง
หาก gather เองถูก cancel งานที่ยังไม่จบภายในถูก cancel ด้วย

[CODE gather_order]
import asyncio  # จัดงานพร้อมกัน
async def job(name, delay):  # งานคืนชื่อ
    await asyncio.sleep(delay)  # รอแบบไม่บล็อก
    return name  # คืนผล
async def main():  # รอทั้งสองงาน
    results = await asyncio.gather(job("A", 0.02), job("B", 0.01))
    print(results)  # แม้ B จบก่อน ผลยังเรียง A, B
asyncio.run(main())  # รันสคริปต์
[END CODE]

[WAIT-01] อยากตรวจ done / pending
ส่ง Task/Future ให้ asyncio.wait(); Python 3.11+ ไม่รับ raw coroutine
done, pending เป็น set จึงไม่มีลำดับ input
ALL_COMPLETED รอทุกงาน; FIRST_COMPLETED กลับเมื่อมีงานจบหรือถูก cancel
FIRST_EXCEPTION กลับเมื่อมีงานจบด้วย exception; ถ้าไม่เกิดรอทั้งหมด
FIRST_COMPLETED อาจมีมากกว่าหนึ่ง task ใน done ณ เวลาที่ผู้รอกลับมาทำงาน
wait(timeout=...) คืน pending และไม่ cancel งานเหล่านั้นเอง

[CODE wait_cleanup]
import asyncio  # ใช้ task และ wait
async def job(delay):  # งานคืน delay
    await asyncio.sleep(delay)  # รอ timer
    return delay  # คืนผล
async def main():  # เลือกงานเสร็จก่อน
    tasks = {asyncio.create_task(job(d)) for d in (0.01, 0.2)}
    done, pending = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)
    print(sorted(t.result() for t in done))  # อ่านผลทุกงานที่จบ
    for task in pending:  # ขอหยุดงานที่เหลือ
        task.cancel()
    await asyncio.gather(*pending, return_exceptions=True)  # รอ cleanup
asyncio.run(main())  # เริ่มโปรแกรม
[END CODE]

[TIME-01] Timeout
wait_for(coro, timeout=seconds) รอผลหนึ่ง awaitable
เมื่อหมดเวลา จะ cancel งานและรอการยกเลิก จึงอาจใช้เวลามากกว่า timeout
Python 3.11+ จับ TimeoutError; อย่าคิดว่า timeout คือ rollback ฝั่ง server
คำขอที่ส่งไปแล้วอาจทำให้ข้อมูลเปลี่ยน ต้องคิดเรื่อง idempotency แยกต่างหาก

[CODE timeout]
import asyncio  # ตั้งเวลารอ
async def main():  # ทดสอบงานช้า
    try:  # รอไม่เกินงบเวลาของผู้เรียก
        await asyncio.wait_for(asyncio.sleep(0.2), timeout=0.01)
    except TimeoutError:  # งานรอถูกยกเลิก
        print("timeout")
asyncio.run(main())  # เริ่ม loop
[END CODE]

[CANCEL-01] Cancel อย่างถูกต้อง
cancel() เป็นคำขอยกเลิก ไม่ใช่ kill ทันที
CancelledError ถูกส่งเข้า coroutine เมื่อมีโอกาส เช่นขณะ await
ใช้ try/finally คืน resource; ถ้าจับ CancelledError โดยทั่วไป raise ต่อ
CancelledError สืบจาก BaseException จึงไม่ถูก except Exception จับตามปกติ
TaskGroup (Python 3.11+) เป็นเนื้อหาเสริม: รอทุกงานและ cancel พี่น้องเมื่อมีงาน fail

repo: Week3/task_01_status.py ถึง task_10_gather_vs_wait.py
และ Week4/foodcourt_01_create_task.py ถึง foodcourt_05_mix_concepts.py

2. คำศัพท์สำคัญก่อนอ่านโค้ด
---------------------------

- คำ: coroutine
  ความหมายง่าย ๆ: function แบบ async ที่ยังไม่เริ่มทำงานจริงจนกว่าจะ await หรือ
  create_task

- คำ: task
  ความหมายง่าย ๆ: coroutine ที่ถูกส่งเข้า event loop แล้ว พร้อมให้ระบบจัดการ

- คำ: event loop
  ความหมายง่าย ๆ: ตัวกลางที่คอยสลับงาน async หลายงาน

- คำ: await
  ความหมายง่าย ๆ: จุดที่งานยอมรอ และเปิดโอกาสให้งานอื่นทำต่อ

- คำ: pending
  ความหมายง่าย ๆ: task ที่ยังไม่เสร็จ

- คำ: done
  ความหมายง่าย ๆ: task ที่เสร็จแล้ว ไม่ว่าจะสำเร็จ พัง หรือถูกยกเลิก

- คำ: cancel
  ความหมายง่าย ๆ: การส่งสัญญาณให้ task หยุดทำงาน

- คำ: callback
  ความหมายง่าย ๆ: function ที่ถูกเรียกอัตโนมัติเมื่อ task เสร็จ

- คำ: latency
  ความหมายง่าย ๆ: ความหน่วง / เวลารอของ network หรือ server

- คำ: HTTP request
  ความหมายง่าย ๆ: การส่งคำขอไปยัง server เช่น GET /price/Beta

Example 8 — task_08_wait.py
---------------------------

แนวคิด
------------

asyncio.wait() ใช้รอหลาย task แบบเลือกเงื่อนไขได้ เช่น “ใครเสร็จก่อนชนะ”

จุดสำคัญ
------------

[โค้ด / แผนภาพ : python]
done, pending = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)

5.3 ทำไมต้องใช้ asyncio.wait()
------------------------------

โจทย์ต้องการ logic แบบ “ใครเสร็จก่อนชนะ”

จึงใช้:

[โค้ด / แผนภาพ : python]
done, pending = await asyncio.wait(
    tasks,
    return_when=asyncio.FIRST_COMPLETED
)
[จบโค้ด / แผนภาพ]

เหตุผลที่ไม่ใช้ gather():

- คำสั่ง: gather()
  ผลลัพธ์: รอทุก server เสร็จทั้งหมด

- คำสั่ง: wait(... FIRST_COMPLETED)
  ผลลัพธ์: รอแค่ server ตัวแรกที่เสร็จ


สำหรับโจทย์นี้ต้องการตัวแรก จึงใช้ wait() ค่ะ

5.4 ทำไมต้อง cancel pending task
--------------------------------

หลังจาก Beta ชนะแล้ว Alpha และ Gamma ยังอาจกำลังรออยู่

ถ้าไม่ cancel:

- งานที่เหลือจะยังค้างใน event loop
- เปลือง resource
- เป็นนิสัยที่ไม่ดีในการเขียนระบบจริง

จึงใช้:

[โค้ด / แผนภาพ : python]
for pending_task in pending:
    pending_task.cancel()
[จบโค้ด / แผนภาพ]

และตามด้วย:

[โค้ด / แผนภาพ : python]
await asyncio.gather(*pending, return_exceptions=True)
[จบโค้ด / แผนภาพ]

เพื่อให้ task ที่ถูก cancel เคลียร์ตัวเองจนจบ ไม่ทิ้ง warning ค้างไว้

Part A — Infrastructure Files

5. foodcourt_api.py — FastAPI Kitchen Server
--------------------------------------------

5.1 หน้าที่ของไฟล์
------------------

ไฟล์นี้สร้าง API server ที่จำลองครัวของศูนย์อาหาร

[โค้ด / แผนภาพ : python]
app = FastAPI(title="🍳 Smart Food Court API")
[จบโค้ด / แผนภาพ]

app คือ FastAPI application ที่ Uvicorn จะนำไปรันเป็น web server

5.2 OrderModel
--------------

[โค้ด / แผนภาพ : python]
class OrderModel(BaseModel):
    student_id: str
    menu_name: str
[จบโค้ด / แผนภาพ]

Pydantic BaseModel ใช้กำหนดรูปแบบ JSON ที่ server ยอมรับ

- Field: student_id
  Type: str
  หน้าที่: รหัสผู้สั่ง

- Field: menu_name
  Type: str
  หน้าที่: ชื่ออาหาร


ถ้าส่ง JSON ขาด field หรือ type ไม่ถูก FastAPI จะตอบ validation error โดยอัตโนมัติ

5.3 KITCHEN_LATENCY
-------------------

[โค้ด / แผนภาพ : python]
KITCHEN_LATENCY = {
    "hainanese_chicken": 0.8,
    "noodle": 1.5,
    "steak": 4.0
}
[จบโค้ด / แผนภาพ]

Dictionary นี้เก็บเวลาทำอาหารของแต่ละร้าน โดยใช้ชื่อร้านเป็น key

5.4 Endpoint cook_food()
------------------------

[โค้ด / แผนภาพ : python]
@app.post("/order/{shop_name}")
async def cook_food(shop_name: str, order: OrderModel):
[จบโค้ด / แผนภาพ]

ข้อมูลมาจาก 2 จุด:

- Parameter: shop_name
  มาจากไหน: URL path
  ตัวอย่าง: steak จาก /order/steak

- Parameter: order
  มาจากไหน: JSON request body
  ตัวอย่าง: student_id และ menu_name


5.5 ตรวจชื่อร้าน
----------------

[โค้ด / แผนภาพ : python]
if shop_name not in KITCHEN_LATENCY:
    raise HTTPException(status_code=404, detail="Shop not found")
[จบโค้ด / แผนภาพ]

ถ้าเรียกชื่อร้านที่ไม่มี เช่น /order/pizza จะได้ HTTP 404

5.6 จำลองการทำอาหาร
-------------------

[โค้ด / แผนภาพ : python]
cooking_time = KITCHEN_LATENCY[shop_name]
await asyncio.sleep(cooking_time)
[จบโค้ด / แผนภาพ]

ต้องใช้ await asyncio.sleep() เพราะ endpoint เป็น async ถ้าใช้ time.sleep() จะ block
event loop และทำให้ request อื่นรอไปด้วย

5.7 Response
------------

Server คืน Python dictionary และ FastAPI จะแปลงเป็น JSON ให้โดยอัตโนมัติ

[โค้ด / แผนภาพ : python]
return {
    "status": "READY_FOR_PICKUP",
    "student_id": order.student_id,
    "shop": shop_name,
    "menu": order.menu_name,
    "cooking_seconds": cooking_time,

8. Task 1 — foodcourt_01_create_task.py

8.1 เป้าหมาย

8.2 Flow
------------

[โค้ด / แผนภาพ : text]
สร้าง coroutine ส่งออเดอร์ข้าวมันไก่
          |
          v
create_task() ส่งงานเข้า event loop
          |
          v
เช็ก .done() ทันที -> ปกติเป็น False
          |
          v
await food_task
          |
          v
รับ response จากครัว
[จบโค้ด / แผนภาพ]

8.3 สร้าง Task
--------------

[โค้ด / แผนภาพ : python]
food_task = asyncio.create_task(

        MY_STUDENT_ID,

    )

8.4 ตรวจ .done()
----------------

[โค้ด / แผนภาพ : python]
food_task.done()
[จบโค้ด / แผนภาพ]

ค่าที่เป็นไปได้:

- False — งานยังทำไม่เสร็จ
- True — งานเสร็จ, error หรือถูก cancel แล้ว

เมื่อเช็กทันทีหลังสร้าง Task โดยทั่วไปจะได้ False เพราะ HTTP request ยังไม่เสร็จ

8.5 รอและรับผล
--------------

[โค้ด / แผนภาพ : python]

await ทำ 2 หน้าที่:

1. รอ Task ให้เสร็จ
2. รับค่าที่ coroutine return กลับมา

10. Task 3 — foodcourt_03_wait_first.py
---------------------------------------

10.1 เป้าหมาย
-------------

ส่ง 3 ออเดอร์พร้อมกัน แต่ต้องการแค่ จานแรกที่เสร็จ

10.2 ทำไมต้องสร้าง Task ก่อน
----------------------------

asyncio.wait() ในโค้ดนี้รับ Task objects:

[โค้ด / แผนภาพ : python]
task1 = asyncio.create_task(...)
task2 = asyncio.create_task(...)
task3 = asyncio.create_task(...)
[จบโค้ด / แผนภาพ]

Task object ทำให้ตรวจสถานะ อ่าน result และเรียก .cancel() ได้

10.3 รอแบบ FIRST_COMPLETED
--------------------------

[โค้ด / แผนภาพ : python]
done, pending = await asyncio.wait(
    [task1, task2, task3],
    return_when=asyncio.FIRST_COMPLETED
)
[จบโค้ด / แผนภาพ]

ผลลัพธ์ถูกแบ่งเป็น 2 set:

- ตัวแปร: done
  เก็บอะไร: Task ที่เสร็จแล้ว

- ตัวแปร: pending
  เก็บอะไร: Task ที่ยังไม่เสร็จ


FIRST_COMPLETED หมายถึงหยุดรอเมื่อมี Task แรกเสร็จ ไม่ได้รอทั้งหมด

10.4 ใครควรเป็นผู้ชนะ
---------------------

จาก latency:

[โค้ด / แผนภาพ : text]
hainanese_chicken = 0.8 วินาที
noodle             = 1.5 วินาที
steak              = 4.0 วินาที
[จบโค้ด / แผนภาพ]

ดังนั้นข้าวมันไก่ควรชนะเมื่อ server ทำงานปกติ

10.5 อ่านผลจากผู้ชนะ
--------------------

[โค้ด / แผนภาพ : python]
winner_task = done.pop()
result = winner_task.result()
[จบโค้ด / แผนภาพ]

- .pop() ดึง Task หนึ่งตัวออกจาก set
- .result() อ่านค่าที่ Task return
- ใช้ .result() ได้อย่างปลอดภัยเมื่อ Task อยู่ใน done และไม่ได้พัง/cancel

10.6 ยกเลิกงานที่เหลือ
----------------------

[โค้ด / แผนภาพ : python]
for task in pending:
    task.cancel()
[จบโค้ด / แผนภาพ]

หลังข้าวมันไก่เสร็จ ก๋วยเตี๋ยวและสเต็กไม่จำเป็นแล้ว จึงส่งสัญญาณยกเลิก

แนวปฏิบัติที่สมบูรณ์ในระบบทั่วไปคือ หลัง cancel() ควรรอเก็บ Task ที่ถูกยกเลิกด้วย:

[โค้ด / แผนภาพ : python]
await asyncio.gather(*pending, return_exceptions=True)
[จบโค้ด / แผนภาพ]

โค้ดปัจจุบันยังไม่มีบรรทัดนี้ แต่ตัวอย่างนี้ช่วยให้เข้าใจว่าการ cancel เป็นคำสั่งร้องขอ
และควรเปิดโอกาสให้ Task จบขั้นตอนยกเลิกอย่างเรียบร้อย

10.7 Expected behavior
----------------------

[โค้ด / แผนภาพ : text]

Cleaning up: Canceling 2 remaining pending orders...
Total waiting time for the first dish: ประมาณ 0.8x seconds.
[จบโค้ด / แผนภาพ]

10.8 wait() ไม่ได้ยกเลิก pending ให้อัตโนมัติ
---------------------------------------------

นี่เป็นจุดสำคัญ:

- asyncio.wait(... FIRST_COMPLETED) แค่หยุดรอ
- งานที่อยู่ใน pending ยังคงทำงานต่อ
- ถ้าไม่ต้องการแล้ว โปรแกรมต้อง .cancel() เอง

2. เอา loop cancel() ออก แล้วสังเกตว่าโปรแกรมรอหรือจบต่างกันอย่างไร
3. เพิ่ม gather(*pending, return_exceptions=True) หลัง cancel

11.6 wait_for() กับ HTTP timeout คนละชั้น

  ค่า: 10.0 วินาที
  หน้าที่: จำกัดเวลารวมของ HTTP request

13. ตารางเปรียบเทียบคำสั่งหลัก
------------------------------

- คำสั่ง: create_task(coro)
  รออะไร: ไม่ได้รอทันที
  คืนอะไร: Task
  หยุดรอเมื่อ: ไม่เกี่ยว
  ยกเลิกงานอื่นอัตโนมัติไหม: ไม่
  ใช้ในไฟล์: Task 1, 3, 5

- คำสั่ง: await task
  รออะไร: Task เดียว
  คืนอะไร: ค่าที่ Task return
  หยุดรอเมื่อ: Task นั้นจบ
  ยกเลิกงานอื่นอัตโนมัติไหม: ไม่
  ใช้ในไฟล์: Task 1

- คำสั่ง: gather(*aws)
  รออะไร: ทุกงาน
  คืนอะไร: list ผลลัพธ์ตามลำดับ input
  หยุดรอเมื่อ: ทุกงานจบ หรือมี exception ตาม behavior
  ยกเลิกงานอื่นอัตโนมัติไหม: ไม่ควรสมมติว่ายกเลิกทุกงาน
  ใช้ในไฟล์: Task 2, 5

- คำสั่ง: wait(tasks, FIRST_COMPLETED)
  รออะไร: Task ชุดหนึ่ง
  คืนอะไร: (done, pending)
  หยุดรอเมื่อ: มีตัวแรกเสร็จ
  ยกเลิกงานอื่นอัตโนมัติไหม: ไม่
  ใช้ในไฟล์: Task 3

- คำสั่ง: wait_for(aw, timeout)
  รออะไร: awaitable เดียว
  คืนอะไร: ผลของ awaitable
  หยุดรอเมื่อ: งานเสร็จหรือหมดเวลา
  ยกเลิกงานอื่นอัตโนมัติไหม: ยกเลิก awaitable เมื่อ timeout ตามกลไก asyncio
  ใช้ในไฟล์: Task 4, 5

- คำสั่ง: task.cancel()
  รออะไร: ไม่ได้รอ
  คืนอะไร: True/False ว่าส่งคำขอยกเลิกได้ไหม
  หยุดรอเมื่อ: —
  ยกเลิกงานอื่นอัตโนมัติไหม: ยกเลิกเฉพาะ Task นั้น
  ใช้ในไฟล์: Task 3


วิธีเลือกใช้แบบจำง่าย
---------------------

[โค้ด / แผนภาพ : text]
อยากให้งานเริ่มก่อน แล้วค่อยกลับมารอ       -> create_task
อยากได้ผลครบทุกงาน                         -> gather
อยากได้จานแรก แล้วแยก done/pending          -> wait + FIRST_COMPLETED

20. Cheat Sheet ก่อนสอบ
-----------------------

[โค้ด / แผนภาพ : text]
async def
    สร้าง coroutine function

await
    รอ awaitable และคืน control ให้ event loop ระหว่างรอ

asyncio.run(main())
    เปิด event loop แล้วรัน main coroutine

asyncio.create_task(coro)
    ส่ง coroutine เข้า event loop และได้ Task object

task.done()
    เช็กว่า Task จบแล้วหรือยัง แต่ไม่ได้ยืนยันว่าสำเร็จ

await task
    รอ Task และรับค่าที่ return

asyncio.gather(a, b, c)
    รอทุกงาน คืนผลตามลำดับ input

asyncio.wait(tasks, return_when=FIRST_COMPLETED)
    รอจนมีตัวแรกเสร็จ คืน done และ pending

task.cancel()
    ส่งคำขอยกเลิก Task

asyncio.wait_for(aw, timeout=n)
    รอไม่เกิน n วินาที ถ้าเกินเกิด timeout

httpx.AsyncClient
    ส่ง HTTP request แบบ async

FastAPI
    สร้าง HTTP API server

POST /order/{shop_name}
